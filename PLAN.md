# План разработки Swayfire-Next (Wayfire Tiling Plugin)

## Архитектура: Баланс Sway/i3 и Hyprland

### Что берём из Sway (модель контейнеров и управление)
1. **Дерево контейнеров (Container Tree):** Строгая иерархия `Workspace -> Tiling Node -> Split Container -> View`. Никакой свободной плавающей каши для тайлинговых окон, детерминированное поведение разделения экрана (горизонтально/вертикально).
2. **Фокус по направлениям (Focus by Direction):** Перемещение фокуса и самих окон через `left / right / up / down` по структуре дерева, а не просто по порядку создания.
3. **Режимы компоновки (Layouts):** Поддержка `splith`, `splitv`, `tabbed`, `stacked` для контейнеров (как в i3/Sway).

### Что берём из Hyprland (интеграция с Wayland, анимации и поведение полноэкранного режима)
1. **Атомарный Fullscreen:** Переход в полноэкранный режим сбрасывает ограничения тайлинга на уровне композитора без сброса состояния плагина (`_NET_WM_STATE_FULLSCREEN` захватывает весь вывод мгновенно).
2. **Динамическая геометрия и отступы:** Плавные гапсы (`gaps`), адаптивные рамки и поддержка оверлеев без перекрытия панелей.
3. **Бесшовный Floating / Toggling:** Мгновенное переключение конкретного окна из тайла в плавающий режим по хоткею (как в Hyprland `togglefloating`), не ломающее остальное дерево.

## Структура проекта
- `src/` — исходный код плагина под современное API Wayfire (0.10/0.11).
- `meson.build` — система сборки.
